# Skill: 音频多媒体生成与播放 (audio-multimedia-generation-playback)

## 触发场景 (Trigger)
- 用户发送语音合成（TTS）请求，例如“帮我把这段话合成为温柔女声语音：...”
- 用户发送音乐生成或音效生成指令，例如“用 Suno 帮我做一首欢快的爵士乐背景音乐”。

## 前置条件 (Preconditions)
- 系统中已集成音频处理服务（如接入了 MiniMax TTS、Suno 等音频生成 Provider）。
- 用户已授权开启浏览器的 Audio 播放权限。

## 调用工具 (Tools)
- `generation.createAudioTask`：发起语音/音乐合成任务。
- `canvas.createAudioCard`：在画布的指定位置创建一个拥有专属 UI（播放器控件、音量、进度条）的音频卡片节点。
- `audio.playbackControl`：向播放器卡片派发播放、暂停、调节进度的操作指令。

## 执行步骤 (Steps)
1. **音频任务发起**：
   - AI 解析用户的配音或音乐描述（如文字内容、音色设定、配乐风格）。
   - 选择匹配的模型服务（如 `minimax-tts`），调用 `generation.createAudioTask` 并等待任务返回。
2. **创建播放器卡片**：
   - 任务成功后，音频文件链接生成（包含音频 originalUrl、apiResultUrl、时长等信息）。
   - 调用 `canvas.createAudioCard`，在画布上挂载一个音频卡片节点。
   - 音频卡片节点上应集成 HTML5 Audio 控制器的自定义 UI：包含播放/暂停按钮、进度拖拽条、音量图标。
3. **并发播放控制（排他机制）**：
   - 当用户点击画布上某音频卡片的“播放”按钮时：
     - 触发主线程播放器监听。
     - 检查画布上是否有其他音频卡片正在播放。
     - **排他操作**：如果存在，必须首先发送暂停（`PAUSE`）指令给其他所有正在播放的音频实例，确保同一时刻只有一个音频卡片在发声。
4. **播放状态同步**：
   - 音频播放过程中，卡片上的进度条和时间刻度实时更新。
   - 播放完毕后，自动重置状态为 `idle`（暂停），不循环播放。

## 安全与体验规则 (Safety & UX)
- **大文件拦截**：对于超长的文本 TTS（如一万字以上），必须进行阶段拦截，并提示用户可能产生的高昂积分扣减或延迟。
- **自动对齐**：新生成的音频卡片应该靠近它的文字 Prompt 卡片或视频卡片，实现“音画成双”的可视化呈现。

## 验证方式 (Validation)
- **TTS 生成验证**：输入“Hello world TTS”，应在画布生成音频播放卡片，点击能听到声音。
- **排他播放验证**：在画布生成两个音频卡片，播放卡片 A 时，点击卡片 B 播放，卡片 A 应瞬间转为暂停状态。
