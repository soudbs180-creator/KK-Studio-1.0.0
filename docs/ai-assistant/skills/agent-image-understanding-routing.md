# Skill: 多模态图像理解路由 (agent-image-understanding-routing)

## 触发场景 (Trigger)
- 用户在 AI 助手输入框发送了包含一张或多张图片，并且伴随文本指令（例如“分析这张图”、“以这几张图为参考生成类似风格的产品图”）。
- 系统调用具有文本交互（Text Invocation）或提示词处理能力的 Agent 模型绑定时。

## 前置条件 (Preconditions)
- 用户的输入流中包含有效的图像数据（如 Base64 编码、画布图片节点引用或外部图片 URL）。
- AI 助手已正确装载模型定义，能访问当前激活的模型提供商（Provider）及其模型配置。

## 调用工具 (Tools)
- `canvas.getState`：读取当前画布，确认用户引用的图像节点是否存在。
- `provider.getModelCapabilities`：查询当前选定模型绑定的元数据（特别是是否支持多模态图像输入 `multimodal` 或 `image_understanding`）。

## 执行步骤 (Steps)
1. **输入解析**：AI 助手解析用户请求，过滤并提取出所有的文本部分及关联的图像资源列表。
2. **多模态能力校验**：
   - 检查解析后的模型绑定接口。
   - 判断该接口是否声明了多模态图像理解能力：
     - 若支持（如 Gemini 1.5 Pro, GPT-4o），则跳转至步骤 3。
     - 若不支持（如仅支持文本的 Llama 3 / 某些老旧文本模型），则跳转至步骤 4。
3. **多模态请求构建**：
   - 将文本与图像以符合对应 Provider 格式的多模态数据（Parts / Contents）进行拼装。
   - 发送 outbound 多模态请求，并等待处理结果。
4. **降级为纯文本处理**：
   - 拦截并剥离图像二进制/Base64 数据。
   - 保持提示词文本部分的完整性。
   - 在向用户或后台发送请求前，发出友好的系统通知：“当前选择的模型不支持图片理解，已为您自动降级为纯文本模式处理。”
   - 仅将文本内容发送给文本模型绑定。

## 安全与成本规则 (Safety & Cost)
- **Token 限制**：由于图像输入消耗大量 Token，AI 助手必须在发送前检查图像的分辨率，建议缩放至 1024x1024 以下。
- **凭证脱敏**：构建 outbound 请求时，确保不泄露任何用户凭证或敏感 key。

## 验证方式 (Validation)
- **多模态测试**：选择 Gemini 3.5 Flash，输入图片与提示词，应成功返回图像的分析内容。
- **降级测试**：选择一个不支持多模态的模型，输入图片与提示词，系统应过滤图片，不向后端 API 发送图片内容，且给出降级警告。
