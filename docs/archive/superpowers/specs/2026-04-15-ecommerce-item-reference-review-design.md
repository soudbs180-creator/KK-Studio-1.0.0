# 电商需求条目级提示词与参考图设计

**日期**: 2026-04-15

**目标**

让电商模块在上传运营需求文件后，能按“每条需求”展示提示词与参考图；当自动识别不到或识别不准时，允许用户对该条需求手动补传参考图；桌面端与手机端都必须保持视口内适配，不出现横向溢出或内容撑出画面。

## 现状

- `xlsx` 解析链路已经能提取单元格图片和浮动图片，并在 `EcommerceAnalysisResult` 中生成 `referenceAssetIds` / `referenceMentions`。
- 当前问题主要在分析确认阶段的 UI 与状态层：
  - 分析结果确认列表只显示文本，不显示参考图；
  - 用户无法对“某一条需求”单独补传参考图；
  - 后续生成虽然会带上自动解析的参考图，但缺少条目级人工补图入口；
  - 手机端和桌面端都没有为“多图 + 多条需求”设计稳定的尺寸约束。

## 设计原则

- 以“条目”为中心，而不是“全局参考图”为中心。
- 自动识别优先，人工补充兜底。
- 列表视图负责总览，详情区负责编辑。
- 所有新增内容都必须在容器内滚动，不允许横向溢出视口。

## 目标体验

### 分析确认阶段

- 左侧条目列表展示：
  - 需求标题或模块标题
  - 提示词摘要
  - 参考图数量
  - 缺图 / 待确认状态
- 右侧详情区展示当前选中条目的：
  - 完整提示词预览
  - 自动识别参考图缩略图
  - 手动补传参考图缩略图
  - 手动补传入口
  - 删除手动补传图入口

### 生成阶段

- 每条需求生成时使用：
  - 该条需求的自动识别参考图
  - 该条需求的手动补传参考图
  - 现有全局产品图 / 全局补充参考图

## 数据设计

新增运行时条目级补图状态，放在 `App.tsx` 的电商运行时状态中：

- key: `sourceRowKey`（主图 `itemId` / A+ `moduleId`）
- value: `File[]`

该状态只用于运行时预览与生成，不回写源 `analysis`，避免污染解析结果。

## 自动参考图来源

- 自动识别参考图继续沿用 `analysis.assets.referenceAssets` 与条目上的 `referenceAssetIds`。
- UI 通过 `referenceAssetIds` 反查 `referenceAssets` 生成缩略图列表。

## 生成接线

- 在现有电商节点运行时素材同步逻辑中，把“条目级手动补图”转换为 `ReferenceImage[]` 并并入该节点的 `referenceImages`。
- 不改变现有全局产品图与全局补充参考图逻辑，只是新增条目级参考图层。

## UI 适配

### 桌面端

- 分析确认面板采用双栏：
  - 左栏：可滚动条目列表
  - 右栏：当前条目详情
- 双栏容器使用 `min-w-0`、`overflow-hidden`、`max-h` 与内部滚动区，防止内容撑开。
- 参考图缩略图区域限制高度，使用网格或横向滚动，不向外扩张。

### 手机端

- 改为单栏上下结构：
  - 上部为条目列表
  - 下部为当前条目详情
- 图片缩略图使用两列网格或横向滚动，容器高度受限。
- 面板与卡片必须带 `min-w-0` 和内部滚动，禁止横向超屏。

## 解析策略范围

本次不重写整套 `xlsx` 解析器，但补一轮更稳的条目级参考图归位 heuristics：

- 优先按空间顺序而不是 XML 声明顺序排序图片；
- 优先保留“明确能归位”的图片；
- 对不明确的情况保留 `reviewWarnings`，让 UI 告知用户手动确认或补图。

## 测试范围

- `xlsx` 条目级参考图顺序 / 归位测试
- 分析确认面板提示词与参考图展示契约测试
- 条目级补图同步到运行时生成素材的契约测试
- 尺寸约束与滚动边界的样式/结构回归测试

## 非目标

- 不做跨条目拖拽重分配参考图
- 不做图片手动排序器
- 不做服务端持久化条目级补图
