# KK Studio 1.7.0 Gate 0 实施计划

> 面向执行 Agent：严格按任务依赖与 TDD 顺序实施。每个任务先形成可观察的失败，再实现最小闭环；不得通过放宽阈值、跳过兼容读取或新增平行 AI Runtime 来换取通过。

**目标：** 在不改变 1.6.1 稳定发布身份、不创建 Desktop 壳和不改造 Spatial UI 的前提下，建立 1.7.0 的版本真相、跨运行时执行权、迁移契约、能力矩阵和可执行性能基线，使 Gate 1 能在可验证的地基上开始。

**架构原则：** 保留 `CanvasRuntimeState`、`DurableGenerationQueue`、`AgentRunStore`、`ToolRegistry` 和 generation-v3 作为现有真相源；新增内容只能是共享契约、适配器、权威校验或只读投影。Desktop I/O 通过 Platform Runtime Port 接入，Web 组件不得散落 Tauri 全局引用。三条执行通道固定为 `local-desktop | paired-desktop | cloud`，Run/Task 投影本身不授予执行权。

**技术栈：** TypeScript、React 19、Vite、Zod、Express、PostgreSQL migration、Vitest/项目测试运行器、Playwright/Chromium smoke、PowerShell、现有治理脚本。

**设计依据：** `docs/superpowers/specs/2026-08-13-kk-studio-1.7.0-spatial-workspace-design.md`

## Gate 0 不包含

- 不创建 `apps/desktop`，不引入 Tauri/Electron 生产依赖；Native feasibility 属于 Gate 1。
- 不把 `config/release-manifest.json` 的稳定发布版本提前改成 1.7.0。
- 不启用 paired/cloud 有副作用命令；现有 paired v1 read-only 协议保持收紧。
- 不改造 Spatial Workspace UI；Gate 0 只提供 Gate 2 所需的 Port、契约和门禁。
- 不恢复被归档的根 `src/`、`apps/api/` 或其它旧入口。
- 不迁移凭据、FileSystemHandle、设备身份或尚未确认的执行权。

## 全局约束

1. 每次开始写入前运行 `npm run agents:status`；工作区非干净时先停止并盘点。
2. 跨层修改顺序固定为 `packages/shared -> packages/api-client -> services/api -> apps/web -> tests -> docs`。
3. `releasedVersion` 在 Gate 6 前保持 `1.6.1`；候选产物只使用派生的 `artifactVersion`。
4. 所有未知 schema、execution target、side-effect class、authority 或 capability 必须 fail closed。
5. 所有 server projection、导入 Run 和迁移任务只能恢复可见状态，不能恢复执行权。
6. 用户目录迁移读取必须只读；不得调用会 create/move/remove/consolidate 的现有加载路径。
7. 性能门禁使用真实 DOM、真实 `getBoundingClientRect()` / `getScreenCTM()` 和可复现 fixture，不以状态快照代替渲染结果。
8. 新公共 API、复杂逻辑和安全判定写“为什么”的注释；单函数原则上不超过 50 行。
9. 不新增生产依赖，除非现有标准库/依赖经过实测无法满足并另有批准记录。
10. 每个任务形成独立可回滚提交；任务完成后更新 OpenSpec/交接，不积攒超大提交。

## 依赖顺序

```text
Task 1 release truth ───────────────┐
Task 2 process launch ──────────────┤
Task 3 shared authority/contracts ──┼─> Task 4/5/6/7/8/9
                                    ├─> Task 10/11/12
                                    └─> Task 13/14/15/16/17
```

Task 1、2、3 可分别由独立 Agent 实施；Task 4–9 依赖 Task 3；Task 11–12 依赖 Task 10；最终 Task 17 必须串行执行。
