# KK Studio API 路由与计费审计规范

> 规范特权大模型 API 请求“零直连前端”的安全屏蔽网关，以及原子级积分预扣和失败回滚退款审计流程。

作为商业化 AI 工作台，API 请求的安全性与账务的绝对精确性是 KK Studio 的底座。

## 1. 路由安全与密钥屏蔽

- **特权密钥网关屏蔽 (Zero Browser Direct Link)**：浏览器端（Vite）和移动端（Expo）不存储或直连任何大模型供应商的特权 API Key。所有请求（文生图、音频合成等）必须由 API Client 统一打包后转发给后端 `services/api/` 网关，在服务端注入密钥并向 Provider 发起真正的生成任务。
- **用户自有密钥隔离**：用户自有 Provider 凭据通过认证 API 写入受保护的服务端存储；浏览器只保留 masked/configured 状态。实际 Provider 请求仍由 `services/api/` adapter 发起，不把解密后的密钥或临时路由返回给页面。

---

## 2. 积分计费与事务审计

后端处理 AI 扣减和结算必须严格遵循以下事务隔离逻辑，防止并发问题：

- **原子级预扣款**：任务发起时，后端率先锁住并预扣该生成件所需的积分余额，不允许并发操作导致负余额。
- **动态报价同源**：确认卡展示的成本和事务预扣必须来自同一服务端价格目录版本；客户端与文档不得硬编码模型积分价格，报价过期时必须重新确认。
- **三阶段事务提交**：
  ```text
  预扣除余额 -> 调用提供商接口 -> 接口成功 (正式结算并归档) / 接口失败 (强制退款回滚，记录失败审计日志)
  ```
- **Webhook 强验签**：在处理外部计费（如 Stripe 订阅或充值）时，所有 Webhook 回调一律使用原始请求体执行签名强验，避免伪造支付包攻击。
